# Internationalization (TH / EN)

The app uses `i18next` + `react-i18next` with two local translation catalogs:

```text
src/
├── components/
│   └── LanguageSwitcher.tsx
├── locales/
│   ├── th.json
│   └── en.json
├── types/
│   └── i18next.d.ts
└── i18n.ts
```

## Runtime behavior

- Default language: `th`
- Last selected language: persisted in `localStorage` under `mahidol-rac-language`
- Supported languages: `th`, `en`
- Translation resources are bundled locally; there is no translation-network request at runtime.

## Type-safe keys

`src/i18n.ts` exports `TranslationKey`, derived from the Thai catalog. The i18next module augmentation in `src/types/i18next.d.ts` wires the catalog into `react-i18next` so invalid keys can be caught by TypeScript.

Example:

```tsx
import { useTranslation } from "react-i18next";

function Example() {
  const { t } = useTranslation();
  return <button>{t("hero.latestActivities")}</button>;
}
```

For data-driven keys, keep a typed translation-key map or cast only at the narrow boundary where a template key is constructed.

## Language switcher

`LanguageSwitcher` renders `TH | EN`, highlights the active language, updates `<html lang>`, changes i18next language, and persists the selection.

## Dependency note

The current CI workflow synchronizes `package-lock.json` with `npm install --package-lock-only` before `npm ci`, so the lockfile remains reproducible when these new dependencies are introduced.
